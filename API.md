### Accordion

A list of items that open and close to show one piece of content at a time, or several with `multiple`, as in frequently asked questions. It follows the ARIA accordion pattern: each item is a button with `aria-expanded` inside a heading (`<h3>` by default), and the panel is a region linked to the button. Tab moves through the buttons, Enter and Space open and close the item, and the arrow keys, Home and End move the focus. Closed panels stay in the document, so the content keeps its state. It accepts a `ref`, which goes to the root, and the attributes of the `<div>`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `items` | `AccordionItem[]` | *required* | Items of the accordion, in the order they appear on screen. Each item has `value` (unique), `title` (the content of the button: text or nodes, such as a logo, a `span` and a `Badge`), `content` (the content of the panel) and, optionally, `disabled`. The `title` sits inside a `<button>`, so only text elements fit, with no other button, link or field, and everything in it is included in the name of the button and of the panel. Closed panels stay in the document, so the content keeps its state. |
| `multiple` | `boolean` | `false` | Lets several items stay open at the same time. Without it, opening an item closes the one that was open, and the open item can still be closed again. |
| `value` | `string[]` | — | Values of the open items when the component is controlled, as a list. It also requires onValueChange. See the Controlled story. |
| `defaultValue` | `string[]` | — | Values of the items that start open, as a list, for use without external control. Without multiple, only the first one is used. |
| `onValueChange` | `(value: string[]) => void` | — | Called with the list of open items after each click. |
| `headingLevel` | `2 \| 3 \| 4 \| 5 \| 6` | `3` | Level of the heading, from h2 to h6, that wraps the button of each item. Choose the level that continues the heading hierarchy of the page. |
| `animation` | `false \| { recipe, tuning }` | `pop` | Animation of the panel, which appears with a fade and a small slide, and of the arrow, which rotates. The height does not animate. false turns it off; { tuning: { duration, distance } } sets the duration in seconds and the slide in pixels. |

Also accepts the other attributes of `<div>`, passed on to the element. Forwards the `ref` to `<div>`.

### Alert

A status message inside the page, in four types (`info`, `success`, `warning` and `error`), with an optional title, icon and close button. For temporary messages that go away on their own, use notifications (`useToast`). It is a `<div>` and accepts the attributes of the `<div>`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `variant` | `'info' \| 'success' \| 'warning' \| 'error'` | `'info'` | Type of the message: it sets the color, the icon and the ARIA role. Only error uses role="alert" and is announced at once; the others use role="status", which screen readers usually do not announce when the alert already appears with its text. For a message that is inserted after the page has loaded and has to be read, pass role="alert". |
| `title` | `string` | — | Highlighted title, above the message. |
| `icon` | `ReactNode` | — | Icon in place of the default one of each type. With null or false, the Alert shows no icon. The icon is decorative (aria-hidden), so the text has to say everything. |
| `onClose` | `() => void` | — | Shows the close button and is called when it is clicked. The Alert does not go away on its own: you remove it. The name of the button comes from labels.closeToast of the UIProvider. |

Also accepts the other attributes of `<div>`, passed on to the element.

### Avatar

A round picture for a person or an entity. It shows the image when there is one and falls back to the initials of the name while the image loads, when it fails and when there is no `src`. With a `name` it is announced as an image with that name; when the name is already written next to it, pass `aria-hidden="true"`. It is a `<span>` and accepts the attributes of the `<span>`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `name` | `string` | — | Name of the person or the entity. It gives the initials of the fallback (the first letter of the first and of the last word) and the accessible name of the avatar. Without it the avatar shows a question mark that assistive technology skips. |
| `src` | `string` | — | Address of the image. While it loads, and if it fails, the avatar shows the initials. Change it and the avatar waits for the new image. |
| `size` | `'sm' \| 'md' \| 'lg'` | `'md'` | Size of the avatar: sm is 2 rem, md is 2.5 rem and lg is 3.5 rem. |
| `children` | `ReactNode` | — | Content shown instead of the initials when there is no image, for example an icon. It does not change the accessible name. |

Also accepts the other attributes of `<span>`, passed on to the element.

### Badge

A small label for a state or a count, such as "New", "Paid" or "3". The color comes from pairs of theme roles, with the contrast checked, and the text always carries the meaning: never rely on color alone. It is a `<span>` and accepts the attributes of the `<span>`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `variant` | `'neutral' \| 'primary' \| 'success' \| 'warning' \| 'error' \| 'info'` | `'neutral'` | Color of the badge, by theme role: neutral is gray, primary uses the main color and success, warning, error and info follow the states. |
| `size` | `'sm' \| 'md'` | `'md'` | Size of the badge: sm is 20 px tall and md is 24 px. |

Also accepts the other attributes of `<span>`, passed on to the element.

### Breadcrumbs

A breadcrumb trail: a `<nav>` with an ordered list, in which the last item is the current page. A long trail hides the middle items behind an ellipsis button that shows the full path.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `items` | `BreadcrumbItem[]` | *required* | The trail, in order. The last item is the current page; the others become links when they have an href. |
| `maxItems` | `number` | `4` | Above this number, the middle items become an ellipsis button that shows the full path. |
| `ariaLabel` | `string` | — | Accessible name of the navigation. The default comes from the UIProvider (labels.breadcrumb). |

Also accepts the other HTML attributes of the root element.

### Button

A button with four variants and three sizes, and press feedback made with CSS only. It is a real `<button>` and accepts its attributes.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `variant` | `'primary' \| 'secondary' \| 'outline' \| 'ghost'` | `'primary'` | Visual style of the button. |
| `size` | `'sm' \| 'md' \| 'lg'` | `'md'` | Size of the button. |
| `fullWidth` | `boolean` | `false` | Takes up the full available width. |
| `animation` | `false \| { recipe, from, tuning }` | `press` | Motion recipe of the button, made with CSS only. Use false to turn the animation off, or { recipe, tuning } with press (scales on press) or lift (rises on hover); other recipes are ignored. The duration, the scale and the distance become the variables --enchase-button-duration, --enchase-button-scale and --enchase-button-distance. Use the controls of the Motion group to experiment. The root element accepts className and style, and exposes data-slot="button". |

Also accepts the other attributes of `<button>`, passed on to the element.

### ButtonLink

A link that looks like a `Button`. It is a real `<a href>`, and goes through the `navigate` of the `UIProvider` for app routes, like the `Link`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `href` | `string` | *required* | Destination of the link, with the same rules as the `Link`: an app route goes to the `navigate` of the `UIProvider`; anchors, the hash of the current page and external URLs are left to the browser. |
| `native` | `boolean` | `false` | Leaves the click to the browser even on an app route. |
| `externalIcon` | `boolean` | `true` | With `target="_blank"`, shows the external link icon after the content. `false` removes only the icon (useful in an icon-only button) and keeps the "opens in a new tab" text for screen readers; in an icon-only link with `aria-label`, put the warning in the label itself. |
| `animation` | `false \| { recipe, from, tuning }` | `press` | Motion recipe of the `Button`. Use false to turn it off, or { recipe, tuning } with press or lift. |
| `variant` | `'primary' \| 'secondary' \| 'outline' \| 'ghost'` | `'primary'` | Visual style, the same as the `Button`. |
| `size` | `'sm' \| 'md' \| 'lg'` | `'md'` | Size, the same as the `Button`. |
| `fullWidth` | `boolean` | `false` | Takes up the full available width. |

Also accepts the other attributes of `<a>`, passed on to the element.

### Card

A surface that groups content, in the variants `default`, `elevated` and `outlined`. Only the `elevated` one rises when the pointer is over it. With `as`, the root becomes another structure tag, such as an `li` in a list of cards. For a card that is clickable as a whole, use `CardLink` or `CardButton`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `as` | `'div' \| 'section' \| 'article' \| 'aside' \| 'nav' \| 'header' \| 'footer' \| 'main' \| 'ul' \| 'ol' \| 'li'` | `'div'` | HTML tag that the root renders, only among the structure tags that the type lists. With `ul` or `ol`, the root loses bullets, margin and indent and gains `role="list"`, which keeps the list semantics in Safari (the `role` of whoever uses it wins). Links and buttons do not go here: use `ButtonLink`, `CardLink` or `CardButton`. |
| `variant` | `'default' \| 'elevated' \| 'outlined'` | `'default'` | Appearance of the card. Only elevated rises when the pointer is over it. |
| `padding` | `string` | — | Inner spacing (any CSS value). Without it, the default spacing applies, and a class of your own always wins over it. |
| `animation` | `false \| { recipe, tuning }` | `lift` | false turns the motion off. { tuning: { duration, distance } } sets the lift (seconds and pixels). The lift only runs with a fine pointer and with no preference for reduced motion. |

Also accepts the other HTML attributes of the root element.

### CardButton

A card that is clickable as a whole and performs an action: a real `<button type="button">`, with the surface of the `Card` (`variant`, `padding` and `animation`, and the same `--enchase-card-*` hooks), a focus ring, hover and pressed layers, and `disabled`. The default `type` is `button`, so it does not submit a form on its own. The content of a `<button>` can only hold text elements (`span`, `strong`, `Badge`, images), with no other button, link or field inside, and everything inside is included in the accessible name. To navigate, use `CardLink`. Inside a list, put the button in an `li`: it fills the height of the item.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `animation` | `false \| { recipe, tuning }` | `lift` | false turns the motion off. { tuning: { duration, distance } } sets the lift of the `elevated` variant (seconds and pixels). The lift only runs with a fine pointer and with no preference for reduced motion. |
| `variant` | `'default' \| 'elevated' \| 'outlined'` | `'default'` | Appearance of the surface, the same as the `Card`. Only the `elevated` one rises when the pointer is over it. |
| `padding` | `string` | — | Inner spacing (any CSS value), as in the `Card`. Without it, the default spacing applies, and a class of your own always wins over it. |

Also accepts the other attributes of `<button>`, passed on to the element.

### CardLink

A card that is clickable as a whole and leads to another page: a real `<a href>`, with the surface of the `Card` (`variant`, `padding` and `animation`, and the same `--enchase-card-*` hooks), a focus ring and hover and pressed layers. It goes through the `navigate` of the `UIProvider` for app routes, like the `Link` (see `native`, `target` and `download`). With `target="_blank"`, the `rel` becomes `noopener noreferrer` and the text "opens in a new tab" is added to the accessible name, with no icon: the design of the card is yours. Everything inside the card is included in the name of the link, so prefer a short title and a short supporting text. The content of an `<a>` accepts headings and paragraphs, but not another link or button. For an action, use `CardButton`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `href` | `string` | *required* | Destination of the link, with the same rules as the `Link`: an app route goes to the `navigate` of the `UIProvider`; anchors, the hash of the current page and external URLs are left to the browser. |
| `native` | `boolean` | `false` | Leaves the click to the browser even on an app route. |
| `animation` | `false \| { recipe, tuning }` | `lift` | false turns the motion off. { tuning: { duration, distance } } sets the lift of the `elevated` variant (seconds and pixels). The lift only runs with a fine pointer and with no preference for reduced motion. |
| `variant` | `'default' \| 'elevated' \| 'outlined'` | `'default'` | Appearance of the surface, the same as the `Card`. Only the `elevated` one rises when the pointer is over it. |
| `padding` | `string` | — | Inner spacing (any CSS value), as in the `Card`. Without it, the default spacing applies, and a class of your own always wins over it. |

Also accepts the other attributes of `<a>`, passed on to the element.

### Checkbox

A styled native checkbox, with a clickable label and an animated check mark. It accepts `ref` and the attributes of the `<input>`. With `indeterminate` it shows the mixed state of a box that summarizes other boxes, such as a select all (see the SelectAll story). With `aria-invalid="true"` the box of an unchecked checkbox takes the color of the error on its border. With `error` the checkbox is marked as invalid by itself and the message shows under the label, and `helperText` shows a hint in the same place. Both sit outside the `<label>`, so the accessible name stays the label text. To choose among several options, use the `CheckboxGroup`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `string` | — | Text of the label. Clicking it also checks the box. |
| `error` | `string` | — | Error message. Marks the checkbox as invalid (aria-invalid), so an unchecked box takes the color of the error on its border, and shows the message under the label, announced as an alert. It replaces the helperText. The message sits outside the `<label>`, in the `<span data-slot="checkbox-field">` that always wraps the label, so the input is never rebuilt when a message comes or goes. |
| `helperText` | `string` | — | Helper text under the label, aligned with its text. It is tied to the checkbox by aria-describedby and disappears when there is an error. |
| `indeterminate` | `boolean` | `false` | Shows the mixed state, for a box that summarizes other boxes. It sets the `indeterminate` property of the native input, so assistive technology reads it as mixed, and it does not change `checked`. A click does not clear it: do that in `onChange`. The property is set on the client, so a mixed box that is rendered on the server looks checked or unchecked until the page hydrates. |
| `wrapperClassName` | `string` | — | Class of the root (data-slot="checkbox"). className stays on the native input (data-slot="checkbox-input"). With a message, it still goes on the `<label>`, inside the column, and not on the outer `<span data-slot="checkbox-field">`. |
| `wrapperStyle` | `CSSProperties` | — | Style of the root (data-slot="checkbox"). style stays on the native input. With a message, it still goes on the `<label>`, inside the column, and not on the outer `<span data-slot="checkbox-field">`. |
| `animation` | `false \| { recipe, tuning }` | `pop` | Animation of the check mark, which grows with a short pop. false turns it off; { tuning: { duration, scale } } sets the duration in seconds and the initial scale. |

Also accepts the other attributes of `<input>`, passed on to the element. Forwards the `ref` to `<input>`.

### CheckboxGroup

A group of checkboxes to choose any number of options that fit on the screen at once. It builds a `<fieldset>` with a title, helper text and an error message, like the other fields, and each option is the `Checkbox` of the library, so Tab moves from one checkbox to the next and Space checks the focused one. The value is the list of the checked values, in the order of the options. It accepts `ref`, which goes to the `<fieldset>`, and the attributes of the `<fieldset>`; `className` and `style` also go to it. The group does not know when a choice is required: validate in your form and pass `error`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `options` | `CheckboxGroupOption[]` | *required* | Options of the group, each one with `value`, `label` and, optionally, `disabled`. The order of the array is the order on the screen. |
| `label` | `string` | — | Title of the group, rendered as the `<legend>` of the `<fieldset>`. Without a visible title, pass aria-label to the group. |
| `name` | `string` | — | Name of the field in the form, the same for all the options, so that each checked value is submitted with it. Without it, the checkboxes have no name and the form does not receive them. |
| `value` | `string[]` | — | Values of the checked options when the group is controlled. It also requires onValueChange. To control it with none checked, pass an empty array. See the Controlled story. |
| `defaultValue` | `string[]` | — | Values of the options checked at the start, for use without external control. See the WithDefaultValue story. |
| `onValueChange` | `(value: string[]) => void` | — | Called with the values of all the checked options, in the order of the options, each time the user checks or unchecks one. A disabled option that is checked stays in the list. |
| `error` | `string` | — | Error message. Marks every checkbox as invalid (aria-invalid), paints the title and the unchecked boxes red and is announced as an alert. It replaces the helperText. See the Validated story. |
| `helperText` | `string` | — | Helper text under the group. It is tied to the group by aria-describedby and disappears when there is an error. |
| `orientation` | `'vertical' \| 'horizontal'` | `'vertical'` | Direction of the list: vertical stacks the options and horizontal puts them side by side, wrapping to a new line when there is not enough room. |
| `animation` | `false \| { recipe, tuning }` | `pop` | Animation of the check mark of each option, which grows with a short pop. false turns it off; { tuning: { duration, scale } } sets the duration in seconds and the initial scale. |

Also accepts the other attributes of `<fieldset>`, passed on to the element. Forwards the `ref` to `<fieldset>`.

### ColorModeProvider

Applies the theme: it injects the `--enchase-*` variables, sets `data-theme` and `color-scheme` on the `<html>` and saves the mode (`light`, `dark` or `system`). The components read the variables, and `useColorMode` returns `{ mode, resolvedMode, setMode, toggleMode }`. The compact density is not a prop: put `data-density="compact"` on the `<html>` yourself (see System/Density in the Storybook). Its variables come with the theme, in the same layer when you pass `cssLayer`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `children` | `ReactNode` | *required* | The app. |
| `theme` | `ThemeInput` | — | Custom theme, such as `{ style, brand, fonts, motion, shape, radius, light, dark }`, the same input that `createTheme` accepts: `style` changes the look of the whole kit (a style imported from `enchase/styles/<name>`, such as `shadcn`), the brand color (`brand`) generates the palette, `shape` picks the shape of the corners (`pill`, `soft` or `square`), `radius` adjusts a radius, and `light` and `dark` adjust colors per mode. What you pass wins over `style`. Every value is validated, and in development the provider warns in the console about contrast and duration. Without it, the default theme applies. |
| `mode` | `'light' \| 'dark' \| 'system'` | — | Controlled mode: `light`, `dark` or `system`. With it, the provider does not save the choice, and you change the value in `onModeChange`. |
| `defaultMode` | `'light' \| 'dark' \| 'system'` | `'system'` | Mode used while there is no saved choice and no `mode` prop. `system` follows the preference of the system. |
| `onModeChange` | `(mode: ColorMode) => void` | — | Called with the new mode when `setMode` or `toggleMode` is used, including with a controlled `mode`. |
| `storage` | `{ getItem, setItem } \| null` | `localStorage` | Where to save the choice, with `getItem` and `setItem`. The default is `localStorage`, read only after mounting. `null` turns off persistence. |
| `storageKey` | `string` | `'enchase-color-mode'` | Key of the choice in the storage. Use the same one in the `ColorModeScript`. |
| `cssLayer` | `string` | — | Name of an `@layer` for the theme variables. Use it with `enchase/styles.layer.css`, as in `cssLayer="enchase-theme"`. CSS of yours without a layer then wins over the theme in any order, tokens of the compact density included: without a layer, `:root[data-density='compact']` beats a token of yours on `:root`. |

### ColorModeScript

Inline script that applies `data-theme` and `color-scheme` on the `<html>` before the first paint, so a page rendered on the server does not show the wrong theme for a moment. Render it at the start of the `<body>` or in the `<head>`, with `suppressHydrationWarning` on the `<html>`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `storageKey` | `string` | `'enchase-color-mode'` | Key read from `localStorage`. Use the same one as the `ColorModeProvider`. |
| `defaultMode` | `'light' \| 'dark' \| 'system'` | `'system'` | Mode used when there is no saved choice. `system` follows the preference of the system. |
| `nonce` | `string` | — | `nonce` of the Content-Security-Policy, so the inline script is accepted. |

### Combobox

A text field with a list of options under it. Typing filters the options, the arrow keys move through the list, Enter chooses the active option, Esc closes the list and Tab leaves the field. It follows the ARIA 1.2 combobox pattern: the focus never leaves the input and the active option is announced through `aria-activedescendant`, so a screen reader keeps reading the field while the list changes. By default it chooses one option and its label fills the field; with `multiple` the chosen options become tags before the input, each with a button that removes it, and Backspace in an empty field removes the last one. Use it instead of the `Select` when the list is long enough to need a search, or when the options come from a server: turn the filter off and search in `onInputChange`. It is not a free text field: the value is always one of the options, and leaving the field puts the label of the chosen option back. The list renders in a portal, like the `Popover`, and accepts `container`. It accepts `ref`, which goes to the input, and the attributes of the `<input>`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `multiple` | `boolean` | `false` | Chooses several options instead of one. The chosen options become tags before the input, the list stays open after a choice and the text is cleared, and `value` and `defaultValue` become lists. See the Multiple story. |
| `value` | `string \| null \| string[]` | — | Value of the chosen option when the field is controlled, or the list of the chosen values with `multiple`. It also requires onValueChange. Pass `null`, or an empty list, to control it with nothing chosen. See the Controlled story. |
| `defaultValue` | `string \| null \| string[]` | — | Option chosen at the start, or the list of the chosen ones with `multiple`, for use without external control. Without it, nothing is chosen. |
| `onValueChange` | `((value: string \| null) => void) \| ((value: string[]) => void)` | — | Called with the value of the option the user has just chosen, or `null` when the user empties the field and leaves it, and with the whole list of the chosen values, in the order they were chosen, with `multiple`. It is not called for an option that is disabled. |
| `options` | `ComboboxOption[]` | *required* | The options, in order. Each one has `value` (unique), `label` (the text that is shown, filtered and read) and, optionally, `disabled`: a disabled option stays in the list, is skipped by the arrow keys and cannot be chosen. The label of a chosen option is remembered, so a list that the app replaces while the user searches does not blank the field or the tags. |
| `label` | `string` | — | Label of the field, tied to the input and used as the name of the list. Without it, give the input an `aria-label`. |
| `labelPlacement` | `'floating' \| 'stacked'` | `'floating'` | Where the label sits: floating (inside the field, moves up to the outline on focus or when filled) or stacked (above the control, with no notch in the outline). Without the prop, the style of the theme (createTheme) applies: floating in the default style and stacked in shadcn. |
| `error` | `string` | — | Error message. Marks the field as invalid (aria-invalid) and is announced as an alert. |
| `helperText` | `string` | — | Helper text. It is tied to the input by aria-describedby and disappears when there is an error. |
| `fullWidth` | `boolean` | `false` | Takes up the full available width. |
| `filter` | `((option: ComboboxOption, query: string) => boolean) \| false` | — | How the options are filtered by what is typed. By default an option stays when its label contains the text, ignoring case and accents. Pass a function `(option, query) => boolean` to decide for yourself, or `false` to show every option, for when the app searches on a server and passes the results as `options`. See the AsyncSearch and CustomFilter stories. |
| `onInputChange` | `(text: string) => void` | — | Called with the text of the input every time the user types, and with an empty text when a choice clears it with `multiple`. Use it to search on a server. Choosing an option in the single mode does not call it. |
| `loading` | `boolean` | `false` | Shows a loading row after the options, marks the list as busy (aria-busy) and announces it in a status region. Use it while the options are on their way. |
| `open` | `boolean` | — | Opens and closes the list, when you control it. Use it together with onOpenChange. |
| `defaultOpen` | `boolean` | `false` | Whether the list starts open, when you do not control it. |
| `onOpenChange` | `(open: boolean) => void` | — | Called with the new state whenever the list opens or closes: typing, a click, the arrow keys, Esc, a choice or a click outside. |
| `container` | `HTMLElement \| (() => HTMLElement \| null) \| null` | — | Element that the overlay renders in, or a function that returns it. ### DatePicker

A field for a single date. The user types it, in the order and with the separators of the language of the `UIProvider` (28/10/2026 in pt-BR, 10/28/2026 in en, and the compact 28102026 or the ISO 2026-10-28 are read too), or presses the button at the end of the field to choose it in a calendar that opens in a dialog. The value is a string in the local ISO form, `YYYY-MM-DD`, with no time and no time zone, the same text that `<input type="date">` gives, or `null` when the field is empty: no `Date` object is involved, so the day never moves with the zone of the machine. The text is read when the user leaves the field or presses Enter, and what is not a date, or is a date that `min`, `max` or `isDateDisabled` rule out, is put back as it was. The calendar is a grid: the arrow keys move by a day and by a week, Home and End go to the start and to the end of the week, Page Up and Page Down change the month and Shift with them the year, Enter and Space choose the day and Esc closes the calendar and gives the focus back to the button. It opens with the focus on the chosen day, or on today. The names of the months and of the weekdays, the first day of the week and the right-to-left mirroring follow the language of the `UIProvider`. The order of the text comes from the language, so it is not the same on every page: the Languages story shows it changing with the provider, and the `locale` prop gives one field a language of its own for the text, the names and the first day of the week (see the Locale story). Today is read in the browser when the calendar opens, so the server renders only the field. The calendar renders in a portal, like the `Popover`, and accepts `container`. It is six weeks tall: when neither side of the field has room for all of it, it opens on the side with more room and its body scrolls. The keys that move the focus (the arrows, Home, End, Page Up and Page Down) bring the day that gets the focus into view, but the focus the calendar takes when it opens does not scroll, so on a very short screen the day it opens on can be out of sight until a key moves the focus. It accepts `ref`, which goes to the input, and the attributes of the `<input>`.

### NumberInput

A field for typing a number, with a label, an error message, helper text and buttons to decrease and increase. It is an `<input type="text">` with `role="spinbutton"` and a numeric keyboard on phones, instead of `type="number"`: the text follows the language of the `UIProvider`, or the `locale` prop of the field (a decimal comma and a period for thousands in pt-BR), it accepts currency and percent through `formatOptions`, and the value comes out as a `number`, or `null` when the field is empty. The arrow keys change the value by `step`; Shift with the arrow keys, Page Up and Page Down change it by `largeStep`; Home and End go to `min` and `max`. The value is confirmed when the user leaves the field or presses Enter, limited to the range and rounded to the decimal places of the format. With `name`, the number goes to the form in a hidden field, without the formatting shown on screen. The buttons stay out of the Tab order, because the keyboard already has the arrow keys, and their names come from `labels.increaseValue` and `labels.decreaseValue` of the `UIProvider`. It accepts `ref`, which goes to the `<input>`, and the attributes of the `<input>`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `value` | `number \| null` | — | Value when the component is controlled; `null` is the empty field. It also requires onValueChange. See the Controlled story. |
| `defaultValue` | `number \| null` | `null` | Initial value, for use without external control. `null` starts with the field empty. |
| `onValueChange` | `(value: number \| null) => void` | — | Called with the confirmed number, or `null` if the field was left empty. It happens when the user leaves the field, on Enter, with the arrow keys and with the buttons, never on every key typed. |
| `min` | `number` | — | Smallest accepted value. What is typed below it goes back to the minimum when the user leaves the field, the decrease button is disabled at it and Home goes to it. With a `min` of zero or more, the minus sign is not accepted. On iPhone the numeric keyboard has no minus sign: to accept negative values, pass `inputMode="text"`. |
| `max` | `number` | — | Largest accepted value. What is typed above it goes back to the maximum when the user leaves the field, the increase button is disabled at it and End goes to it. |
| `step` | `number` | `1` | How much the value changes with the arrow keys and with the buttons. Steps count from `min` (or from 0), and the decimal places of the step go into the format. A value that is not positive is replaced by 1. |
| `largeStep` | `number` | — | Large step, used by Shift with the arrow keys and by Page Up and Page Down. Without it, ten times the `step` applies. |
| `formatOptions` | `NumberInputFormat` | — | Format of the number, as in `Intl.NumberFormat`: `style` (`decimal`, `currency` or `percent`), `currency` (a code such as `USD`), `currencyDisplay`, `minimumFractionDigits`, `maximumFractionDigits` and `useGrouping`. | `locale` | `string` | — | BCP 47 tag, such as `de`, `en-IN` or `pt-BR`, that gives this field a language of its own: the decimal separator, the grouping, the digits and the place of the currency and percent signs, in what is shown and in what is typed. | `label` | `string` | — | Label of the field, associated with the input for screen readers. |
| `labelPlacement` | `'floating' \| 'stacked'` | `'floating'` | Where the label sits: floating (inside the field, moves up to the outline on focus or when filled) or stacked (above the control, with no notch in the outline). Without the prop, the style of the theme (createTheme) applies: floating in the default style and stacked in shadcn. |
| `error` | `string` | — | Error message. Marks the field as invalid (aria-invalid) and is announced as an alert. |
| `helperText` | `string` | — | Helper text. It is tied to the field by aria-describedby and disappears when there is an error. |
| `fullWidth` | `boolean` | `false` | Takes up the full available width. |
| `steppers` | `boolean` | `true` | Shows the decrease and increase buttons, and the spoken announcement of the new value when one of them is used. Without them, the keyboard still has the arrow keys. |
| `wrapperClassName` | `string` | — | Class of the root (data-slot="number-input"). className and style stay on the input (data-slot="number-input-field"). |

### Progress

Shows how far a task has come, as a bar or as a ring. With a `value` it is determinate; without one it is indeterminate and loops until the task ends. It is a `progressbar` with `aria-valuenow`, `aria-valuemin` and `aria-valuemax`, and the indeterminate one leaves `aria-valuenow` out. Give it a name that says what is progressing, with `aria-label` or `aria-labelledby`; without one the name is the `loading` label of the `UIProvider`. The bar eases to a new value and the ring follows it, and the loop of the indeterminate state follows the `shimmer` recipe for the bar and the `spin` recipe for the ring. With reduced motion the loop becomes a pulse of the whole bar or ring. It is a `<div>` and accepts the attributes of the `<div>`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `value` | `number` | — | How far the task has come, from 0 to `max`. A value out of the range is held at the nearest end. Leave it out for an indeterminate progress, when you cannot tell how long the task takes. |
| `max` | `number` | `100` | Value that means the task is done. A number that is not above 0 is replaced by 100. |
| `variant` | `'linear' \| 'circular'` | `'linear'` | Shape of the progress: a bar that fills its row, or a ring that sits in the text. |
| `size` | `'sm' \| 'md' \| 'lg'` | `'md'` | Size of the progress. For the bar it sets the thickness (sm is 0.25 rem, md is 0.5 rem and lg is 0.75 rem) and for the ring the diameter (sm is 1.5 rem, md is 2.5 rem and lg is 3.5 rem). |
| `animation` | `false \| { recipe, tuning }` | `shimmer (bar), spin (ring)` | Loop of the indeterminate state. false turns it off and leaves a still, faded bar or ring. { tuning: { duration } } sets the seconds of one cycle. The determinate bar and ring also stop easing when it is false. |

Also accepts the other attributes of `<div>`, passed on to the element.

### Slider

Picks one number in a range by dragging a thumb, clicking the track or using the keyboard. It is a `slider` with `aria-valuemin`, `aria-valuemax` and `aria-valuenow`: the arrow keys move by one `step`, PageUp and PageDown by a tenth of the range, and Home and End go to the ends. In a right-to-left page the left and right arrows swap, and the track fills from the right. On a touch screen it moves with a tap or a horizontal drag, so a swipe up or down that starts on it still scrolls the page. It picks one value only: there is no range with two thumbs. Give it a name with `label`, `ariaLabel` or `aria-labelledby`. When the number is not enough for a person who cannot see the thumb, such as a price or a temperature, pass `formatValue` so that `aria-valuetext` says it with its unit. It accepts `ref`, which goes to the root, and the attributes of the `<div>`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `value` | `number` | — | Value of the slider when it is controlled. It also requires onValueChange. A value outside the range, or off a step, is shown at the nearest allowed one. See the Controlled story. |
| `defaultValue` | `number` | — | Value at the start, for use without external control. Without it, the slider starts at `min`. |
| `onValueChange` | `(value: number) => void` | — | Called with the new value each time it changes, by pointer or by keyboard, already rounded to the step and held inside the range. It is not called when the value stays the same. |
| `min` | `number` | `0` | Smallest value. |
| `max` | `number` | `100` | Largest value. When it is not a multiple of `step` away from `min`, the largest value that can be picked is the last step before it. |
| `step` | `number` | `1` | Distance between two values. It accepts fractions, such as 0.1. A number that is not above 0 is replaced by 1. |
| `label` | `string` | — | Visible name of the slider, above the track. It also names the thumb for screen readers. |
| `ariaLabel` | `string` | — | Name of the slider for screen readers when there is no visible `label`. Without any name, pass aria-labelledby. |
| `formatValue` | `(value: number) => string` | — | Turns the value into the text that is shown with `showValue` and read to screen readers as `aria-valuetext`, such as 30% or $120. Without it the number is shown as it is and `aria-valuetext` is not set. |
| `showValue` | `boolean` | `false` | Shows the current value beside the label. It is hidden from screen readers, which read the value of the thumb. |
| `name` | `string` | — | Name of the field that carries the value in a form. Without it nothing is submitted, and a disabled slider does not submit it either, as a native control would not. |
| `disabled` | `boolean` | `false` | Disables the slider: the thumb leaves the Tab order and neither the pointer nor the keyboard change the value. |
| `animation` | `false \| { recipe, tuning }` | `fade` | Animation of the filled part and of the thumb when the value changes by a key or by a click. Dragging follows the pointer with no delay. false turns it off; { tuning: { duration } } sets the duration in seconds. |

Also accepts the other attributes of `<div>`, passed on to the element. Forwards the `ref` to `<div>`.

### Table

A semantic data table, built from `columns` and `rows`: a `<table>` with a caption (`<caption>`), column headers (`scope="col"`), optional row headers and cells that accept any content through the `cell` function. It is generic: the row type flows from the `rows` to the columns. When the table is wider than the space available, the container scrolls horizontally and becomes a focusable region with the name of the table, for keyboard-only users. It does not order or paginate the data itself: with `sortable` columns, `sort` and `onSortChange` it draws the sort buttons and marks `aria-sort` while the app orders the `rows`, and for pages you use the `Pagination` next to it. `stickyHeader` keeps the header in view while the rows scroll, `loading` swaps the rows for placeholders, and `selectedKeys` adds a column of checkboxes, with a select all in the header, that the app keeps in state. It accepts a `ref`, which goes to the container, and the attributes of the `<div>`; `className` and `style` go to it as well.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `columns` | `TableColumn<Row>[]` | *required* | Columns of the table, in the order they appear on screen. Each one has `key` (the field of the row that it shows), `header` (text or nodes, such as an abbreviation or a unit in small type) and, optionally, `cell` (a function that returns the content of the cell of a row), `align` (`start`, `center` or `end`), `width` (CSS width, such as `8rem`), `rowHeader` (its cells become row headers) and `sortable` (puts a button in the header, which holds the header, so it cannot hold a button or a link). Without `cell`, the column shows `row[key]` as text. |
| `rows` | `Row[]` | *required* | Rows of the table, one object per row. The row type links the columns to the rows: `TableColumn<Order>[]` with `rows` of `Order`. |
| `getRowKey` | `(row: Row, index: number) => string \| number` | — | Returns the stable key of a row, such as the id, so React can reuse the row when the order changes. Without it, the position is used. |
| `caption` | `string` | — | Title of the table, rendered as a `<caption>` above it, which also gives the accessible name. For a name that is not shown, pass ariaLabel. |
| `ariaLabel` | `string` | — | Name of the table for screen readers, useful when there is no caption. With both, ariaLabel is used. |
| `empty` | `ReactNode` | — | Content shown in a cell that spans all the columns when there are no rows. Without it, only the header appears. |
| `size` | `'sm' \| 'md'` | `'md'` | Density of the rows: sm is compact and md is the default. The compact density of the whole kit (`data-density` on the `<html>`) keeps the sm rows at the same height. |
| `striped` | `boolean` | `false` | Alternates the background of the rows to help follow a long row. |
| `sort` | `TableSort` | — | How the rows are ordered now: `{ key, direction }`, where `key` is the key of a column and `direction` is `ascending` or `descending`. The table marks that column with `aria-sort`, whether it has a button or not, and shows the direction on its button. The rows themselves are yours to order. See the Sortable story. |
| `onSortChange` | `(sort: TableSort) => void` | — | Called when a sort button is activated, with the sort that was asked for: ascending for a column that is not sorted and the opposite direction for the sorted one. It does not change anything by itself: order the rows and pass the new `sort` back. Without it the buttons do nothing. |
| `stickyHeader` | `boolean` | `false` | Keeps the header at the top of the table while the rows scroll under it. It only works when the table has a height limit, such as `style={{ maxBlockSize: "16rem" }}`: without one the page scrolls and the header goes with it. |
| `loading` | `boolean` | `false` | Swaps the rows for placeholder rows, as many as the rows or five when there are none, marks the table `aria-busy` and announces the loading label. The `empty` content waits until it stops loading. Pass a boolean always, even false, so the announcement works: the status region is created when the prop is not undefined. |
| `selectedKeys` | `TableRowKey[]` | — | The keys of the selected rows, in a list that the app keeps. Passing it, even empty, adds a first column with a checkbox per row and a select all in the header, which is checked when every row is selected and mixed when only some are. A key is what `getRowKey` returns for the row, or its position when there is no `getRowKey`, so pass `getRowKey` when the rows can be sorted or filtered. Keys of rows that are not in the table, such as those of another page, are kept. A selected row has `data-selected`. The table is not a grid, so there is no `aria-selected`. |
| `onSelectedKeysChange` | `(keys: TableRowKey[]) => void` | — | Called with the whole new list of keys when a row box or the select all box is used. The names of the boxes come from the `selectRow` and `selectAllRows` labels, and each row box also reads the row header. |

Also accepts the other attributes of `<div>`, passed on to the element. Forwards the `ref` to `<div>`.

### ToastProvider

Holds the queue of notifications and the region where they appear (`role="region"`, named by `labels.notifications`, not a live region). Two hidden announcers, which exist before the first notification, read the text of each one aloud: `role="status"` for success, info and warning, and `role="alert"` for error. The countdown of all the notifications stops while the pointer or the keyboard focus is anywhere in the region. The `success`, `error`, `warning` and `info` methods of `useToast` open the notifications, and the message can be text or nodes.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `children` | `ReactNode` | *required* | The app. The components inside it use `useToast` to open notifications. |
| `container` | `HTMLElement \| (() => HTMLElement \| null) \| null` | — | Element that the overlay renders in, or a function that returns it. The function runs after the overlay mounts, never on the server and never during a render, so it can look up an element rendered by the same tree, and it runs again when the prop changes. Without it, or when it is null, the overlay renders in the `body`. Use it to keep the overlay inside an element with its own theme: it inherits the CSS variables of that element, which an overlay in the `body` does not. An ancestor of the container with `transform`, `filter` or `contain` becomes the containing block of the fixed positioning and moves the overlay, and one that creates a stacking context (`z-index`, `opacity`, `isolation`) confines the `z-index` of the overlay to it. |
| `position` | `'top-start' \| 'top-end' \| 'bottom-start' \| 'bottom-end'` | `top-end` | Corner of the window where the notifications stack: `top-end` (the default), `top-start`, `bottom-end` or `bottom-start`. Start and end follow the direction of the page, and the notifications slide in from that side. The oldest one is always first from top to bottom. |
| `limit` | `number` | — | Most notifications on the screen at once, from 1 up. The others wait in a queue, in order, and appear as the visible ones close; a waiting one is neither announced nor counted down until it appears. Without it, there is no limit. |

### Tooltip

A text tooltip for a trigger, opened by pointer and by focus. It gives the trigger an accessible description and adjusts its position near the edge of the screen. Esc closes an open tooltip but is not intercepted: a `Modal` or `Popover` around the trigger receives the same key.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `text` | `string` | *required* | Text of the tooltip. With describe on, it also becomes the accessible description of the trigger. |
| `children` | `ReactNode` | *required* | The trigger. It sits inside a div (data-slot="tooltip-trigger") and, with describe on, receives aria-describedby. |
| `position` | `'start' \| 'end' \| 'top' \| 'right' \| 'bottom' \| 'left'` | `'top'` | Side of the trigger where the tooltip appears. start and end follow the direction of the UIProvider (left and right in ltr, the reverse in rtl). Near the edge of the screen the tooltip flips to the other side and shifts to fit. |
| `describe` | `boolean` | `true` | Turns on the accessible description of the trigger. Turn it off when the trigger already has the same text as its name, like an icon-only button. |
| `container` | `HTMLElement \| (() => HTMLElement \| null) \| null` | — | Element that the overlay renders in, or a function that returns it. The function runs after the overlay mounts, never on the server and never during a render, so it can look up an element rendered by the same tree, and it runs again when the prop changes. Without it, or when it is null, the overlay renders in the `body`. Use it to keep the overlay inside an element with its own theme: it inherits the CSS variables of that element, which an overlay in the `body` does not. An ancestor of the container with `transform`, `filter` or `contain` becomes the containing block of the fixed positioning and moves the overlay, and one that creates a stacking context (`z-index`, `opacity`, `isolation`) confines the `z-index` of the overlay to it. |
| `animation` | `false \| { recipe, tuning }` | `pop` | false turns off the transition. The default recipe is "pop", a fade with a light scale; { recipe: "fade" } only fades; { tuning: { duration } } changes the duration in seconds. |
| `openDelay` | `number` | `100` | Milliseconds between entering the trigger and showing the tooltip. 0 shows it at once. With another tooltip open, or one closed less than 300 ms ago, the next one opens without waiting and without animation. |
| `closeDelay` | `number` | `120` | Milliseconds between leaving the trigger and hiding the tooltip. Moving the pointer onto the tooltip itself keeps it open. |
| `className` | `string` | — | Class of the element that wraps the trigger (data-slot="tooltip-trigger"). |
| `style` | `CSSProperties` | — | Style of the element that wraps the trigger. |
| `bubbleClassName` | `string` | — | Class of the tooltip (data-slot="tooltip-bubble"). You can also style it by data-slot, data-position and data-state. |
| `bubbleStyle` | `CSSProperties` | — | Style of the tooltip. |

### UIProvider

Configuration shared by all the components: language and texts, breakpoints, motion and navigation (`navigate` and `currentHref`). It is optional: without it, the components use English, the Bootstrap 5 breakpoints, automatic motion and links that reload the page.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `children` | `ReactNode` | *required* | The app. The components read the configuration of the nearest `UIProvider`; without one, the defaults apply. |
| `motion` | `{ mode?, preset?, recipes? }` | `{ mode: 'auto', preset: 'standard' }` | Motion of all the components: `{ mode, preset, recipes }`. With `mode`, `"auto"` respects `prefers-reduced-motion` and `"never"` turns off all motion. `preset` scales the duration and the distance: `"off"`, `"subtle"`, `"standard"` or `"expressive"`. `recipes` adjusts `fade`, `pop`, `slide`, `press`, `lift`, `resize`, `spin` and `shimmer`, as in `{ slide: { distance: 48 } }`. |
| `locale` | `Locale` | `en` | Language, in the format `{ locale, dir, messages }`, such as `ptBR` and `en` from `enchase/locales`. It sets the accessibility texts of the components and the direction (`ltr` or `rtl`) they use. The `locale` tag also decides how dates and numbers are written: a malformed tag, or one that the `Intl` of the environment does not know, falls back to `en` with no error. The `dir` of the `<html>` is still up to the app. |
| `labels` | `Partial<UILabels>` | — | Replaces individual texts of the locale, such as `{ closeModal: "Dismiss" }`. |
| `breakpoints` | `Partial<Breakpoints>` | `{ xs: '0px', sm: '576px', md: '768px', lg: '992px', xl: '1200px', xxl: '1400px' }` | Width of each breakpoint (`xs`, `sm`, `md`, `lg`, `xl` and `xxl`), in any CSS width value, such as `{ md: "1000px" }`. They apply to `Container`, `Layout`, `Navbar`, `Sidebar` and `useBreakpoint`. |
| `navigate` | `(href: string) => void` | — | Called with the `href` when there is a plain click on an app route (an `href` that starts with `/`). Connect it to your router, as in `(href) => router.push(href)`. Without it, the links reload the page. |
| `currentHref` | `string` | — | Current path of the app. It marks the active item of the menus (`aria-current="page"`), derives the `Breadcrumbs` of the `Layout` and makes a link with a hash to its own page (`/docs#props`) scroll without going through the `navigate`. Without it, the hash is compared with the URL of the browser. |

### useToast

```ts

```

Opens notifications through the `success`, `error`, `warning` and `info` methods, for example `success("Saved", 3000)`, and each one returns the id of the notification, which `removeToast(id)` accepts to close it and `update(id, patch)` accepts to change it. The message is text or nodes. `duration` is in milliseconds and 0 keeps the notification open until someone closes it. The third argument takes `className`, `style`, `action` (`{ label, onClick }`, a button that runs `onClick` and closes the notification) and `dismissible` (false removes the close button and the close by click or Esc). `update(id, patch)` changes `message`, `type`, `duration`, `action`, `dismissible`, `className` or `style` in place, and a new `duration` restarts the countdown. `promise(task, { loading, success, error })` shows `loading` as a notification that does not expire and turns it into `success` or `error` when the promise settles (both can be functions of the value or of the reason), and returns the same promise. | `promise` | `<T>(task: Promise<T>, messages: ToastPromiseMessages<T>, options?: ToastOptions) => Promise<T>` |

## CSS hooks

Optional CSS variables that each component reads to change a measure, a font, a corner or a timing without writing CSS on top. The theme does not declare them: without a value, the component uses the default in the table, and a default that points to a theme token keeps following an override of that token. With `data-density="compact"` on the `<html>`, some of them take a lower value (see System/Density in the Storybook), and a hook of yours wins over it. The name is `--enchase-<data-slot>-<property>`, with the name of the `data-slot` of the part and, when there is more than one size or variant, its suffix (`--enchase-switch-thumb-size`, `--enchase-button-padding-inline-md`). Experimental until version 1.0: a name can change in a minor version.
