# Forms with react-hook-form and Zod

The fields of Enchase work with [react-hook-form](https://react-hook-form.com) and a [Zod](https://zod.dev) schema, through `@hookform/resolvers`, with no adapter. The form below is a real component of this repository: tests fill it in and check it, and a consumer project compiles the same code against the packed package, so the code under it is what runs. It uses react-hook-form 7 and the Zod 4 API (`z.email()`, `z.iso.date()`); those packages are not part of `enchase`, so your app installs them. In a Next.js app (App Router), put `'use client'` at the top of the file, because it uses hooks.

## How each field is wired

- **`register`** for `Input`, `Select` and `Checkbox`. They forward `ref` and take the attributes of the native element, so `{...register('email')}` brings `name`, `onChange`, `onBlur` and `ref`.
- **`Controller`** for `Combobox`, `DatePicker` and `RadioGroup`. They report the choice in `onValueChange`, not in an `onChange` event, so pass `value={field.value}` and `onValueChange={field.onChange}` by hand. Do not spread `field` into them: the compiler accepts it, but in the `Combobox` and the `DatePicker` the `onChange` of `field` then runs on the change events of the inner text input, and the form gets the typed text (`'Bra'`, not `'br'`). In the `RadioGroup` spreading only seems to work, because the `change` event of the radios bubbles up to the `<fieldset>`.
- **The message** goes in the `error` prop. The field marks itself with `aria-invalid`, shows the message as an alert and drops the `helperText` while the error is there. Both `errors.email?.message` and `fieldState.error?.message` are `string | undefined`, which the props accept, also with `exactOptionalPropertyTypes`.
- **The `Checkbox`** has no `error` prop, so the recipe sets `aria-invalid` and shows the message in an `Alert` that `aria-describedby` points to.

## What the schema says

- **Empty answers.** When nothing is chosen, `Combobox` and `DatePicker` hold `null`, a `Select` and a `RadioGroup` hold `''` and a `Checkbox` holds `false`. The schema accepts `null` and `false` as input and pipes them into the rule that rejects them with the message, and `''` fails `min(1)`. So `z.input` has the values the controls hold and `z.output` is the typed result.
- **The date.** The value of the `DatePicker` is the local ISO text `YYYY-MM-DD`, with no time and no time zone, so `z.iso.date()` checks it and the typed result is a `string`: there is no `Date` to convert.
- **The browser stays out.** `noValidate` on the `<form>` leaves the validation to the schema.
