# Migrating to 0.10

From 0.9.x. This page only quotes the notes of the release, and the whole of them are in the [changelog](../../CHANGELOG.md#v0100).

## Does it break?

> Breaking: `enchase/theme` exports 16 values and 31 types now, and 37 internal helpers left it (the list is below).

> `enchase/theme` no longer exports `cssVar`, `variableName`, `hexColor`, `springPosition`, `springSettleTime`, `cssVariablesRule`, `fontVariablesRule`, `layoutVariablesRule`, `colorVariables`, `fontVariables`, `layoutVariables`, `shadowVariables`, `themeVariables`, `vars`, `globalStylesCss`, `mergeMotion`, `motionTransitions`, `toMilliseconds`, `isValidColor`, `isValidDistance`, `isValidDuration`, `isValidEasing`, `isValidFontFamily`, `isValidFontSize`, `isValidFontWeight`, `assertValidColor`, `assertValidFontFamily`, `assertValidFontSize`, `assertValidFontWeight`, `canMeasureContrast`, `componentContrast`, `contrastChecks`, `textContrast`, `formatContrastIssues`, `formatMotionIssues`, `maxUiDuration` and `maxPlayfulDuration`.

> The entry used to be `export *` of an internal module, so they were public by accident and undocumented.

> Nothing changes at runtime outside that list, and the weight is the same.

## If you call `validateTheme` or `validateMotion`

> `validateTheme` and `validateMotion` still return the problems they find; only the two functions that turned them into text left.

## If you write by hand an object that stands for `useToast`

> For TypeScript, the message of a `Toast` is a `ReactNode`, and an object written by hand to stand for what `useToast` returns, with a `message` of type `string` or without `update` and `promise`, no longer matches the type.

## If you test an app that has a `ToastProvider`

> For tests of an app: with a `ToastProvider` mounted, `getByRole('alert')` and `getByRole('status')` find the two announcers too (empty until a toast is announced), so an assertion about a toast is better written against its text.

## If you wrote your own `Locale`

> `removeTag` is optional in `UILabels`, so a `Locale` written for an older version stays valid and falls back to English, as `increaseValue` and `decreaseValue` did in 0.6.0.

## If you link to the Storybook or to `API.md`

> The ids of the Storybook change with the titles (`Componentes/...` is `Components/...`, `Sistema/...` is `System/...`, and the stories of the `Navbar`, `Toast`, `Sidebar` and the system pages have English names), so a link to an old page of the Storybook breaks; the anchor of `API.md` for the CSS hooks is `#css-hooks`.
