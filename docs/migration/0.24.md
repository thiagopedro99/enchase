# Migrating to 0.24

From 0.23.x. This page only quotes the notes of the release, and the whole of them are in the [changelog](../../CHANGELOG.md#v0240).

## Does it break?

> Two changes in behavior, and none in the API.

Your code compiles and runs as before, and an app that passes no style looks different after the upgrade. Each change has a section below, with its note quoted and the code to change, if you want the look of 0.23 back.

## `default-style`

> The look that the components have with no style is new, and it is called Lapidado: cool neutral surfaces, a 1 px border with a short shadow, the brand color only in action, selection and focus, 10 px corners on controls and 16 px on cards, a light fillet on the filled button, and the label above the field.

> `default-style`: the look of 0.23, Material 3, is the new `material3` style, in `enchase/styles/material3`. With it, `createTheme` writes the theme of the default of 0.23, character for character, with and without a `brand` and with `shape: 'pill'`.

To keep the look of 0.23, pass the style to the theme. It is the only line to change:

```tsx
import { ColorModeProvider } from 'enchase'
import { material3 } from 'enchase/styles/material3'

<ColorModeProvider theme={{ style: material3 }}>
  <App />
</ColorModeProvider>
```

An app that uses the static `enchase/theme.css` instead of the provider gets Lapidado from that file. To keep Material 3 there, write the css of the theme with `themeCss(createTheme({ style: material3 }))` from `enchase/theme`, at build time, and load it in place of `enchase/theme.css`.

## `default-label-placement`

> `default-label-placement`: the label of `Input`, `NumberInput`, `Select`, `Textarea`, `Combobox` and `DatePicker` sits above the field (`stacked`) when neither the field nor the style says where it goes. The `material3` style keeps it floating, a field takes `labelPlacement="floating"`, and a style of your own sets `defaults.labelPlacement`.

With the `material3` style nothing changes. With the new default, a field that must keep the floating label says so:

```tsx
<Input label="Name" labelPlacement="floating" />
```

## If you use `shadcn`, `workbench` or a style of your own

> The `shadcn` and the `workbench` styles write the theme of 0.23, except for one hook that `shadcn` gains, below. A style of your own made with `defineStyle` starts from the same base as in 0.23, so it does not change: `createTheme({ style: defineStyle({}) })` is the default of 0.23.

A style of your own that should start from the new default spreads it: `defineStyle({ ...enchase, radius: { button: '0.25rem' } })`, with `enchase` from `enchase/styles/enchase`.

## If you set hooks on `:root`

> A hook that your app declares on `:root` wins over them in any order of the stylesheets, with and without the compact density, as it did when the default look declared no hook.

Nothing to change. A hook set on a class or on an element of your own wins as before.

## If you ejected components

The copies made by `enchase eject` keep the css of the source as it was when you copied it, so they do not change until you copy them again, and `enchase eject --diff` shows what the source has that your copy does not. The look of an ejected component still comes from the theme, so it follows the new default like the others. See [EJECT.md](../../EJECT.md).
