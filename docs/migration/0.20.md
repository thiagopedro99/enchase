# Migrating to 0.20

From 0.19.x. This page only quotes the notes of the release, and the whole of them are in the [changelog](../../CHANGELOG.md#v0200).

## Does it break?

> No breaking change, and the stable API did not lose anything: `npm run check:api` against 0.19.1 reports 21 keys of `exports` and none removed, 12 stable entries with 1,090 lines of declarations and none removed, changed or widened, the same 1,219 `--enchase-*` names, 277 `data-slot` names and 575 hooks of the styles, and the three stylesheets are byte for byte those of 0.19.1.

> The paths `enchase/experimental/*` keep working, with a deprecation warning in the editor and in `tsc`, until 1.0 removes them.

> This is the third minor version in a row without a break, of the three that 1.0 asks for (0.18, 0.19 and 0.20).

## If you import the hooks from `enchase/experimental/*`

> `enchase/experimental/<name>` is now an alias of `enchase/headless/<name>`: it exports the very same hook and types (the JavaScript of the old entries did not change, and the bundle of `useTabs` is 2,884 bytes minified by both paths), and the declarations of the old entries carry `@deprecated` on every export, so the editor and `tsc` flag each import and say where to go.

> To move, change `experimental` to `headless` in the import and nothing else.

## If you use the eject command

> `enchase eject` is stable since 0.20: it freezes its commands and options, the format of `enchase.eject.json` (`format: 1`) and that every component that `eject/index.json` lists is ejectable and compiles next to the package, and it does not freeze the layout of the folders and the files of a component, which stays outside the API, with `--diff` as the way a copy meets a change.

> A copy still imports neither `enchase/headless` nor `enchase/experimental`, and `npm run test:eject` fails when one does.
