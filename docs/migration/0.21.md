# Migrating to 0.21

From 0.20.x. This page only quotes the notes of the release, and the whole of them are in the [changelog](../../CHANGELOG.md#v0210).

## Does it break?

> No breaking change, and the stable API did not lose anything: `npm run check:api` against 0.20.0 reports 21 keys of `exports` and none removed, 12 stable entries with 1,118 lines of declarations (28 more than the 1,090 of 0.20.0: `iconOnly`, `label` and 26 `ref`) and none removed or changed, one widened (`VisuallyHiddenProps`, an alias that gained an optional part), 1,223 `--enchase-*` names (4 more) and 279 `data-slot` names (2 more) and none removed, the same 575 hooks of the styles, and `theme.css` is byte for byte the one of 0.20.0.

> `styles.css` differs from 0.20.0 only by five new rules, for the label of the `SegmentedControl`, and three changed lines, for the padding of the `Card`, both listed below.

> One behavior does change, and it is the one to check: in the `Combobox`, typing now makes the first enabled option that is left the active one, so Enter chooses it where it used to submit the form, and an app whose users type and press Enter to submit will have an option chosen instead; with the list closed, with nothing typed, with no enabled match or while `loading`, Enter works as before.

> `check:api` does not see behavior, so this is not in `api-breaks.json`.

## If you use the `Combobox` in a form

> Typing "nod" in a list of Node.js, Deno, Bun and Angular leaves Node.js active, and Enter chooses it without submitting the form; typing "no" leaves Node.js and Deno, with Node.js active and the arrows starting from it.

> A disabled first match is skipped, and when every match is disabled, or there is none, nothing is active and Enter submits the form.

> Enter does nothing while an input method composes text (`isComposing`), as in the `DatePicker`.

## If you pass `padding` to a `Card`, `CardButton` or `CardLink`

> What the page draws is the same in every case measured: a spec in Chromium, Firefox and WebKit compares the computed padding with and without the prop on the card, on the body of a card with a header, in `CardButton`, in `CardLink` and in nested cards (an outer `padding="0"` does not reach the inner ones), and it passes against the code of 0.20.0 too, except for the one case that is the point of the change: a class of yours, also inside a media query, now wins over the prop, which an inline padding never allowed.

> The prop is a fixed value, and a value that changes with the screen size goes through the hook `--enchase-card-padding` in CSS, as `API.md` says.

## If you pass a `ref`

> In the floating layers it holds the panel, which exists only while the layer is open, so it is `null` while closed and goes back to `null` when the exit animation ends: the dialog panel in `Modal`, `ConfirmModal` and `Drawer`, the panel of the modal `Sidebar`, the content panel of the `Popover` (the trigger is the `children`, which take their own ref), the `role="menu"` panel of the `Menu` and the bubble of the `Tooltip`.

> `Sidebar`, `Modal`, `Drawer`, `Popover`, `Tooltip` and `Menu` did not pass a `ref` to the DOM before.

## If you ejected a component

> The kit of `enchase eject` changes with the components that the release touched: `eject/files` has the same 304 files as in 0.20.0, and 44 of them have new content, in 27 component folders.

> The copies of `Modal` and `ConfirmModal`, `Drawer`, `Popover`, `Tooltip`, `Loading`, `Sidebar` and `Navbar` now carry `utils/mergeRefs.ts`, which `eject/index.json` lists for each of them (the `Navbar` through the `DrawerLayer` that it shares with the `Drawer`), and the copy of the `Menu` carries no new file, because it imports the `Popover` from the package.

> The files that `eject/index.json` lists for every other component and the `format: 1` of the manifest do not change, `test:eject` compiles the 48 copies, and `enchase eject --diff` shows what changed to whoever ejected a component before.

## If you test with screen readers

> Screen readers: two things changed in what a screen reader meets, and neither was heard.

> In the `Combobox`, `aria-activedescendant` now points at the first match while the user types (the pattern that the ARIA Authoring Practices call automatic selection), so a screen reader announces an option as soon as the list filters, and Enter chooses it. And the label of the `SegmentedControl` names its group through `aria-labelledby`.
