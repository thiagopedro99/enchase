# Migrating to 0.23

From 0.22.x. This page only quotes the notes of the release, and the whole of them are in the [changelog](../../CHANGELOG.md#v0230).

## Does it break?

> Four changes in behavior, and none in the API.

The cascade is described in [STYLING.md](../../STYLING.md). Each change has a section below, with its note quoted and the code to change, if your app has it.

## `element-selectors`

> `element-selectors`: an element selector of yours, such as `button` or `h1`, loses to every rule of the library. Before 0.23 it could win over the rules that the library wrote inside `:where()`.

A rule that must win is a class, on the element that needs it:

```css
button {
  border-radius: 0;
}

.square {
  border-radius: 0;
}
```

```tsx
<Button className="square">Save</Button>
```

## `rest-class` and `state-class`

> `rest-class`: a rest class of yours that comes before the library's stylesheet now wins over the library's rest rules, and over the disabled look of `Button`, as a class that comes after it already did.

> `state-class`: a class of yours that names a state, such as `.save:hover`, `.save:focus-visible` or `.save:disabled`, now wins over the library's rule for that state, also when it comes before the library's stylesheet.

A class without the state still loses to the hover and focus rules of the library, so a class that must change them names the state:

```css
.save {
  background: #0b6bcb;
}

.save:hover {
  background: #084f94;
}
```

## `link-states`

> `link-states`: a rule of yours on an element state, such as `a:hover` or `:focus`, no longer changes the hover and the press of the `Link` component, nor the focus ring of the links of `Breadcrumbs`, `Navbar`, `Sidebar`, `Footer` and `Layout`, and of the system stories. A class that names the state does.

If a rule on `a:hover` or on `:focus` stopped changing a link of the library, put the state on a class of your own, and give the class to the link:

```css
.plain-link:hover {
  text-decoration: underline;
}
```

```tsx
<Link href="/docs" className="plain-link">Docs</Link>
```

## If you ejected components

The copies made by `enchase eject` keep the CSS of the source as it is written, so nothing changes in them. See [EJECT.md](../../EJECT.md).

## If you use Tailwind 4

Declare the order of the layers before the imports, and import the layered stylesheet, `enchase/styles.layer.css`. The order is in [STYLING.md](../../STYLING.md#tailwind-4).
